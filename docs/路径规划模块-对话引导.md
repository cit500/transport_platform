## 0. 你的任务（一句话）

在 Plant_v2 平台内，把「重车通行评估」模块中**虚构的路径**替换为**基于真实路网数据的路径规划**：起点 → 终点，考虑桥隧通行限制与道路属性，输出推荐/备选路线的边序列、里程、时间与沿线桥隧判定，并让该图模型可被后续模块（韧性 OD 分析等）复用。

## 1. 必须先知道的现状（哪些是假的）

**后端 `HeavyService.java`（114 行，要替换的核心）**

- `judge()` 桥隧通行规则是**真的**：荷载利用率 ≥85% → CONDITIONAL、超设计荷载 → BLOCKED、隧道净空不足 → BLOCKED、缺参数 → PENDING_DATA、`service_status=CLOSED` → BLOCKED。这部分**保留复用**；
- `recommendedDistance = 25.8 + blocked*3.1 + conditional*0.8` 是**编造的公式**，与路网无关；
- `evaluate()` 从不产生任何几何路径——**返回结果里没有路线坐标**。

**前端 `HeavyView.vue`**

- 起点/终点是**自由文本输入框**，默认值写死为 `'渝中区 · 解放碑'` → `'江北区 · 观音桥'`，后端完全不解析它；
- 地图上的"推荐路径/备选绕行"是 **3 个写死的经纬度点**（`[29.5634,106.5518] → [29.5901,106.6055]`），画线走 `mapRef.drawRoutes([{points, style}])`，该方法会自动 fitBounds，可继续复用；
- 路线卡片直接读 `result.recommendedDistance / alternativeDistance`。

## 4. 图算法选型建议

1. **不要引入 GraphHopper / OSRM / pgRouting**——1.2 万边的图，Java 内直接实现 Dijkstra（小根堆）+ A*（球面距离启发）即可，毫秒级响应，零运维成本；
2. 建图建议抽成独立的 `RoadGraphService`（启动时或懒加载全量边进内存：邻接表 + 边属性 + geometry），**不要每次请求查全表**；数据变更后提供重建入口；
3. `one_way`：单向边只建正向弧；双向边建两条反向弧；
4. 权重按现有 `preference` 三档映射：`DISTANCE` → `length_m`；`TIME` → `length_m / design_speed_kmh`；`SAFETY` → TIME/DISTANCE + 惩罚项（BLOCKED 边在 `avoidBlocked=true` 时直接剪枝，CONDITIONAL 边按 `allowConditional` 决定通行或加罚，权重语义需与用户确认，见 §6）；
5. **连通性风险**：OSM 裁剪网可能存在孤立子图——建图时做连通分量标记，OD 落在不同分量时返回明确错误（"起点与终点不连通"），不要静默失败；
6. 起终点吸附：自由坐标 → 最近路网节点（或最近边投影），把吸附误差写进返回结果；
7. 输出：路径边序列 → 用 `asset_road_relation` 反查沿线桥隧 → 复用 `judge()` 出沿线判定 → 汇总里程/时间；几何取各边 `geom` 拼接（或逐边返回折线）。

## 5. 接口契约（尽量向后兼容现有前端）

`POST /api/heavy/evaluate` 现有入参（保留）：`taskName, grossWeightTon, vehicleLengthM, vehicleWidthM, vehicleHeightM, axleCount, plannedSpeedKmh, origin, destination, avoidBlocked, allowConditional, preference, vehicleProfileId`。

返回结构**保留** `rows/pass/conditional/blocked/pending/conclusion/recommendedDistance/alternativeDistance`（前端路线卡片直接读这些字段），**新增**：

```json
{
  "routes": [
    { "key": "recommended", "label": "安全推荐路径",
      "distanceKm": 0, "durationMin": 0,
      "edgeIds": [/* 途经 road_edge.id，供沿线桥隧与高亮 */],
      "points": [[lat,lng], ...] },
    { "key": "alternative", "label": "备选绕行路径", ... }
  ],
  "originNode": {"id":0,"longitude":0,"latitude":0},
  "destinationNode": {...},
  "unreachableReason": null
}
```

前端把 `points` 交给 `mapRef.drawRoutes()` 即可画线（推荐线 `#45e4ff` weight 5、备选线 `#a187ff` 虚线，沿用现有样式常量）。

## 6. 起步前需要向用户确认的问题

1. **起终点输入形态**：保留文本框但改为"搜索路网边/节点/行政区"？还是地图选点（TransportMap 已有点选基础设施 `pickMode`）？
2. **SAFETY 权重的量化定义**：仅避开 BLOCKED？CONDITIONAL 加固定罚？还是按桥隧荷载利用率连续加权？
3. **CONDITIONAL 设施策略**：绕行 / 直行 / 由 `allowConditional` 决定（现状语义）？
4. **备选路线条数与生成策略**：K 最短路？惩罚重复求一次？"推荐+1 备选"够不够？
5. **市内 OD 不可达的产品表现**：提示并推荐最近高速入口？
6. **图模型复用**：韧性模块将来要做 OD 可达性与受损路网重算——确认 `RoadGraphService` 按"无损伤/带损伤边集"两种状态设计，避免韧性阶段重写。
