## 一、方向定位（先讲清楚这是什么课题）

课题主体：**构建一套面向桥隧结构灾损评估与重载通行评估的力学仿真智能体（Agent）**。对象是自然灾害（地震、泥石流）导致的桥隧结构损伤，以及重载车辆通行对桥隧的荷载效应；Agent 要完成的闭环是：

> 自然语言任务 → 任务模式与荷载类型识别 → 参数解析 → 力学建模 → 荷载工况生成 → 有限元计算与监控 → 结果提取 → 损伤/超限评定 → 通行判定与绕行建议 / 报告输出

桥梁院项目（平台的 LLM 助手、易损性计算、路网与设施绑定、异步任务框架）是**背景与可复用底座**，不是课题本身。

**专业适配性论证（答辩必问"这和计算机系做 Agent 有什么区别"）**：
- 不比代码，比**领域知识封装**：Agent 工具链的每一步（建模参数化、荷载生成、损伤判据、结果判读）都是力学内容，计算机系做不了；
- 范式对标：航空航天领域已有"AI for CAE / 仿真自动化"趋势（气动外形优化智能体、结构分析副驾），本课题是同范式在桥梁工程灾损与通行评估上的垂直落地；
- 工程力学出身的优势恰恰是"知道仿真流程里哪一步会错、错在哪个力学假设上"——这是 Agent 自修复能力设计的核心知识来源。

**四条选题原则**：
1. **Agent 为壳、仿真为核**——力学相关章节篇幅不低于一半（本构、工况、损伤判据、结果分析），防"套壳大模型"质疑；
2. **闭环可演示**——至少一条端到端链路现场跑通：输入一段任务描述，输出损伤状态/超限判定/绕行建议；
3. **评测可量化**——成功率、与人工基准的偏差、耗时节省、自修复收敛轮数；没有评测的 Agent 论文立不住；
4. **仿真内核算力可控**——优先 OpenSees（Python 脚本化、开源免费，地震时程/冲击时程/移动荷载均可实现，天然适合 Agent 生成代码），Abaqus 作为隧道连续介质问题的可选扩展。

## 二、共同技术底座（所有选题共用，先建后分）

```
┌─ 交互层：自然语言任务输入 / 结果问答
├─ Agent 核：LLM（函数调用），任务模式识别 · 荷载路由 · 工具编排
├─ 工具层：建模器 · 荷载工况生成器 · 求解器接口 · 结果提取器 · 损伤/超限评定器 · 报告器
├─ 约束层：参数 Schema 校验（堵幻觉）· 错误自修复循环 · 关键步人工确认
├─ 仿真内核：OpenSees 脚本 / 项目已有易损性计算（两级评估中影响线预筛程序）
└─ 数据层：analysis_task / analysis_result（任务提交-监控-落库，平台已有）
```

## 三、候选选题（三个主选题 + 一个方法学选题）

### 选题 1｜面向桥隧多灾种与重载作用的有限元仿真评估智能体（旗舰题，原选题 1+3 融合）

**拟解决的问题**：地震、泥石流引起的结构损伤评估与重载车辆的通行评估，历来是两套流程、两种深度。本课题用**一套 Agent 统一承载两类任务、三类荷载，且全部落到有限元**：

**任务模式 A —— 单结构灾损评估**：
- "墩高 30 m 的连续梁桥，PGA 0.2g，评估各损伤状态概率"（地震）
- "泥石流流速 8 m/s、流深 3 m 冲击该桥墩，评估结构响应与损伤"（泥石流）

**任务模式 B —— 重载通行评估（路线级）**：
- "130 t 重载车组通过 G65 某路段，能否通行？不能通行给出绕行建议"
  → 沿线桥隧自动提取 → 逐设施荷载工况生成 → 有限元荷载效应分析 → 超限判定 → 路线级汇总 + 绕行建议

**主要工作**
1. **统一任务表示与荷载路由**：设计"任务模式 × 结构/路线对象 × 荷载类型 × 工况参数"的任务 Schema；Agent 识别模式与荷载类型后路由到对应分析策略——地震 → 时程分析/Pushover；泥石流 → 冲击时程/等效静力；重载 → 静力布载/移动荷载分析。**路由正确性本身是评测指标之一**；
2. **"一模型多工况"的模型复用架构**：同一桥梁/隧道 FEM 模型 + 三类可插拔荷载模块（地震动记录及调幅、泥石流冲击荷载时程生成、车队轴载布置与移动荷载）。这是本课题区别于单灾种工具的关键设计，也是答辩时最讲得清的创新点；
3. **两级评估架构（原选题 3 的工程智慧并入）**：路线级重载评估采用"影响线/规则预筛 → 可疑设施有限元复核"的层级——先用自编影响线程序快速筛掉明显安全的设施，仅对临界设施调用 FEM 深算。既控制算力，又体现工程合理性，本身可作为论文的一个方法点；
4. **路线级批量评估链路**：沿线桥隧提取（复用平台路网-设施绑定）→ 批量提交 → 结果汇总 → 通行判定与绕行建议 → GIS 可视化（复用平台 Leaflet）；
5. **有限元内核**：OpenSees 为主；隧道连续介质问题（泥石流堆积/冲击）作 Abaqus Python 扩展；
6. **基准算例与评测**：三类荷载各 5—8 个人工金标准算例（自己先人工算完）+ 路线级案例 2—3 条（用刘张浩资料中的人工评估结果作对照）；评测指标：任务成功率、荷载路由正确率、损伤/超限指标偏差、路线判定一致率、端到端耗时；给出**跨灾种/跨模式对比结论**——Agent 在哪类任务上更可靠、失败集中在哪个环节。

**力学内容占比**（论文第二、三、四章，篇幅过半）：
- 桥墩纤维截面建模与 Pushover/时程分析（地震线）；
- 泥石流冲击荷载模型选型（流体动压 + 大块石冲击公式对比）与冲击时程构造（泥石流线）；
- 车队布载、移动荷载效应、控制截面超限判定与规范设计荷载对比（重载线）；
- 三线共用的损伤指标与 DS 分级口径。

**可复用**：LLM 助手框架、易损性计算流程、莫东霖桥梁模型与泥石流流速—流深框架、刘张浩重车资料（车队参数 + 人工评估案例）、平台路网与桥隧-路段绑定、`analysis_task`/`analysis_result`、GIS 前端。

**回填平台量全组最大**：灾害模块增强（地震/泥石流）+ **重车模块从"规则检查"直接升级为"有限元评估"**——后者是平台现存最明显的短板之一，论文成果与项目交付互证。

**规模控制（必读）**：三类荷载 × 两种任务模式 ≈ 六条链路，这是本课题最大风险。**分期策略**：核心先做"地震（模式 A）+ 重载（模式 B）"两条主线，泥石流作为扩展章；先桥后隧。答辩时三类齐演示最漂亮，但**宁可两类做透，不要三类都半生不熟**。

**难度**：★★★（全组最高）　**算力需求**：中（OpenSees 为主；两级评估架构进一步压算力）。
**适合**：投入最大、想做出完整系统的学生。**这也是全组的"总装题"**。

### 选题 2｜基于大模型脚本生成与错误自修复的有限元自动建模方法（技术核心题）

**拟解决的问题**：LLM 生成的 OpenSees/Abaqus Python 脚本一次成功率有多高？加上"运行报错 → 诊断 → 修复 → 重跑"的自修复循环后能提高到多少？

**主要工作**
1. 构建脚本生成的支撑体系：参数 Schema + 模板库 + 知识库检索（规范条文、建模惯例），对比"纯提示生成"与"模板 + 检索增强生成"两种模式；
2. 实现**错误自修复循环**：解析求解器报错与物理异常（不收敛、结果量级异常、模态缺失），映射到力学原因（网格、边界、本构、时步），生成修复动作；
3. 评测：脚本一次生成成功率、平均修复轮数、最终收敛率、修复前后结果误差；错误分类统计（语法错 / 接口错 / 力学错）；
4. 给出"哪些错误类型 Agent 能自修复、哪些必须人工介入"的**能力边界结论**。

**可复用**：莫东霖的建模流程（转化为模板库）、平台知识库检索。
**亮点**：自修复循环的能力边界分析是全组最有"方法学"味道的结论，直接决定工程可用性。
**难度**：★★★　**算力需求**：低—中（大量小算例）。
**适合**：偏方法研究的学生。**选题 1 的核心子模块，可独立成题也可合并。**

### 选题 3｜多灾种桥隧损伤情景的批量仿真调度智能体（编排调度题）

**拟解决的问题**：给定灾害情景描述（地震 PGA 分布 / 泥石流流速流深范围）或路线级评估请求，Agent 如何自动规划仿真矩阵（哪些结构 × 哪些工况）、批量提交、失败重试、汇总成损伤分布与条件易损性？

**主要工作**
1. 研究仿真任务的自动分解与编排：情景 → 结构清单 × 工况矩阵 → 任务 DAG → 批量提交与调度；
2. 实现失败处理与结果汇总：任务失败诊断、自动重试策略、部分失败下的结果完整性保障；
3. **仿真内核直接调用项目已有易损性计算**（参数化曲线，不需新建 FEM 模型）→ 算力风险显著低于选题 1/2；
4. 评测：调度效率（对比串行）、任务成功率、端到端产出（损伤分布图/条件易损性曲线集）。

**可复用**：`analysis_task`/`analysis_result` 框架（现成）、灾害模块计算、韧性工具（扩展损伤→功能映射）。
**亮点**：**与合同"任务异步计算与运行监控"指标直接对齐**，成果即平台功能；智能性体现在"编排与调度"而非建模，与选题 1/2 分工清晰。
**难度**：★★☆　**算力需求**：低（复用已有计算）。
**适合**：想做系统与调度、力学深度要求适中的学生。

---

### 选题 4｜仿真智能体的评测基准与能力边界分析（方法学题，建议并入前三题）

**主要工作**：构建"桥隧灾损与重载仿真任务基准"（按难度分级：参数查询 → 单算例 → 参数扫描 → 多灾种编排 → 路线级评估），定义指标体系（成功率/精度/效率/自修复轮数），做消融实验（有无知识库、有无自修复、不同 LLM），输出能力边界图。

**定位**：单独成题偏薄，**建议作为选题 1 或 2 的第五章**；若学生人数富余且偏评测兴趣，可独立。

**推荐度**：若只选一个，**首选选题 1**（含 2/4 的核心内容与原选题 3 的应用价值）；求稳选 3；系统向选 3。

## 五、避坑五条（Agent 课题特有）

1. **防"套壳"质疑**：力学章节（建模方法、荷载与损伤判据、结果分析）篇幅 ≥ 一半；每个 Agent 工具都写出其背后的力学依据，答辩时能脱开 PPT 讲清楚"为什么这个工具这样设计"；
2. **LLM 复现性**：固定模型版本与解码参数（温度 0 等），论文附录给出完整 Prompt、工具定义与运行日志；评测结论要标注"针对本文所用模型版本"；
3. **幻觉控制**：所有进入仿真内核的参数走 Schema 校验器与量纲/范围检查，**不允许 LLM 自由生成的数值直接进模型**；关键步骤保留人工确认点（人机协同，不宣称全自动）；
4. **评测先行**：先定基准算例集与金标准（自己人工算），再开发 Agent——顺序颠倒的后果是最后一个月没有时间评测，论文只剩系统演示；
5. **做垂直不做通用**：明确限定在"桥隧灾损与重载仿真评估"这一垂直域，不追求通用 Agent 框架；垂直领域的深度正是答辩优势。

## 六、与纯力学版选题的关系

上一版（纯力学口径）的六个仿真内核——桥梁地震参数敏感性、IDA 不确定性、泥石流冲击、落石冲击吸能、明洞参数化、代理模型——均可作为本版 Agent 课题的**算例域与基准任务来源**（例如：选题 1 的基准算例即取自"参数敏感性"的参数矩阵；选题 2 的脚本模板即来自莫东霖建模流程）。两版并不互斥：**Agent 版是"怎么做仿真"，纯力学版是"仿真算什么"**。
