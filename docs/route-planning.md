# 基础路径规划（2026-11-11）

## 本期实现

重车页面 `/heavy` 改为基础路径规划工作台。左侧三个面板依次为路径规划、沿线桥梁和沿线隧道；地图沿用背景路网，独立叠加实际路径折线。底部支持拖动调整高度及“路径方案信息 / 路网与计算状态 / 评估日志”三个页签。路径统计展示总里程、经过边数、节点数、桥隧数量和算法耗时，不受清单状态筛选影响。

右侧三个面板依次为重车任务配置、沿线桥隧判定、执行保通路径规划。车辆参数在居中弹窗编辑，支持保存、另存方案，方案保存在浏览器 localStorage，键为 `plant.heavy.vehicle-profiles.v1`。每次单设施评估接收当前车辆参数，并在保存评估时将车辆快照写入数据库。车辆参数尚未参与最短路径筛选。非法参数与存储失败会明确提示。未评估设施显示待核查，右侧状态筛选作用于左侧两类清单。保通路径重算留待后续迭代。

地图模式与叠加图层通过 `MapLayerControl` 组件复用灾害页交互。重车页分别控制行政边界、区县名称、规划路线（“路网”）、背景路网和沿线桥隧；区县名称不依赖边界开关。点击设施仅平移并最多轻微放大一级，已有较大缩放不再继续放大。地图与底栏高度控制共用 `useMapPanelResize`，支持指针拖动与方向键调整，并清理页面卸载时的监听。

起终点支持经纬度输入、地图分别点选、交换和重置。修改坐标会立即清空旧结果。经纬度只校验全球合法范围；不设置吸附距离阈值，也不限制重庆范围。输入点与匹配节点之间用虚线连接，不计入里程。

本期不使用车辆参数、荷载/净空规则、单向限制、转向限制、设施运营状态或人工禁行条件筛选路径。界面不再展示旧的安全推荐、车辆通行结论或示例备选路线。

## 数据与算法

- 后端读取 `road_node` 与完整 `road_edge`，包含主线、匝道及复合分类；不使用 `/api/map/roads` 的筛选结果建图。
- 所有边建立两个方向的弧，以 `length_m` 为非负权重，通过优先队列 Dijkstra 搜索。保留平行边及原始边 ID。
- 地理坐标通过 MySQL `ST_Longitude` / `ST_Latitude` 读取，避免 SRID 4326 的轴顺序导致 ST_X / ST_Y 误用。
- 两个输入坐标分别用球面距离匹配最近节点，节点距离相同时按节点 ID 查询顺序稳定选取。
- 拓扑首次请求懒加载为不可变缓存。道路拓扑、节点坐标或边长更新后，当前阶段需重启后端刷新缓存。
- 确定路径后，仅查询经过边的 GeoJSON 几何和桥隧绑定，不向前端传输全量节点用于求路。道路几何按行进方向组织，以分段折线绘制，避免跨段凭空连线。
- 按路径边顺序提取 `asset_road_relation`，同一设施仅保留首次出现。无坐标但有绑定的设施仍列出，定位时使用首次经过绑定边的中间顶点。
- `PathFinder.solve` 保留每次查询的禁用边集合扩展点；当前 API 不接收或执行人工禁行。

## 接口

`POST /api/heavy/plan`（只读，不生成分析任务）

```json
{
  "originLongitude": 106.560283,
  "originLatitude": 29.542699,
  "destinationLongitude": 106.558966,
  "destinationLatitude": 29.552919
}
```

返回字段：

| 字段 | 说明 |
| --- | --- |
| `status` / `reachable` / `message` | SUCCESS、SAME_NODE 或 UNREACHABLE；同一节点是可达的零距离结果 |
| `origin` / `destination` | 输入坐标、匹配节点及 `snapDistanceM` |
| `distanceM` / `distanceKm` | 数据库路径边长度之和；不可达时为 null |
| `nodeIds` / `edgeIds` / `edgeCount` | 按行进顺序的节点及道路边 |
| `segments` | 每条边的 ID、起止节点、长度、道路属性及 `[纬度,经度]` 折线 |
| `assets` | 沿线设施去重清单，含 firstEdgeId、sequence 和定位坐标，不含车辆评估结论 |
| `bridgeCount` / `tunnelCount` | 去重后的沿线桥隧数量 |
| `network` | 计算图规模、双向简化标记、构建时间与耗时 |
| `timings` | 节点匹配、Dijkstra 求解、服务方法总耗时（ms） |

输入缺失、非有限值或经纬度越界返回 400；拓扑或道路几何异常返回 503。不同连通子网返回正常的 UNREACHABLE 响应，前端清空路径并显示原因。同节点返回 0 条边、1 个节点、0 里程。

旧 `/api/heavy/evaluate` 和任务读取接口保留供兼容，新的页面调用独立的规划与单设施模拟接口。规划结果保持只读。用户保存的单设施模拟结果写入独立标记的分析记录，详见下节。

## 单设施通行模拟（2026-11-12）

左侧桥梁、隧道每行提供“通行评估”。居中弹窗读取数据库设施档案，展示当前重车参数、设施公共属性与桥梁或隧道专业参数。开始评估后，进度条随读取、计算响应及保存阶段更新。结论提供可通行、条件通行、禁止通行、待核查四种状态。

`HeavySimulationService.evaluateParameters(assetParameters, vehicleParameters)` 接收完整设施档案（专业字段位于 `detail`）与归一化车辆参数，当前均匀随机返回四种状态，方法标识为 `RANDOM_SIMULATION_V1`。后续专业方法可在该入口替换。界面始终标注随机模拟。

用户可以保留随机结论，也可以修改有效状态并填写调整理由。原计算结论、人工有效状态与理由分别保存，支持恢复原结论。重新评估时可选择保留或清除人工调整。关闭未保存结果时提示确认。

保存后同步更新左侧清单标签、地图设施颜色及常驻标签、右侧统计与单设施详情。右侧支持总览和单设施切换，也可以选择设施重新打开评估弹窗。重车任务配置面板仅管理车辆方案。

### 接口与保存

所有路径均以 `/api` 为前缀。

| 接口 | 用途 |
| --- | --- |
| `GET /heavy/assets/{id}/context` | 设施档案与 `assetVersion` 指纹 |
| `POST /heavy/assets/{id}/assess` | 接收 `{scenarioId, vehicle}`，返回含随机结论、参数快照及 `draftToken` 的只读草稿 |
| `POST /heavy/assessment-saves` | 接收 `{scenarioId, vehicle, draftToken, overrideStatus?, overrideReason?}`，保存结果并返回 `savedAssessmentId` |
| `POST /heavy/assessment-saves` | 修改已保存记录时以 `savedAssessmentId` 替换 `draftToken`，追加历史并保存 `parentAssessmentId` |
| `POST /heavy/assessment-validations` | 接收 `{scenarioId, vehicle, savedAssessmentIds}`，返回仍可复用的 `validAssessmentIds` |

`vehicle` 包含 `profileName`、`grossWeightTon`、`vehicleLengthM`、`vehicleWidthM`、`vehicleHeightM`、`axleCount`、`plannedSpeedKmh`。数值必须为有限正数，轴数必须为整数。人工状态与随机结论不同时，必须填写1至500字调整理由。

草稿签名有效期30分钟，后端重启后未保存草稿失效。保存时重新核对情景、车辆快照和设施数据指纹。设施档案变化后需重新评估。

模拟记录沿用现有 `analysis_task` 与 `analysis_result`，任务类型为 `OTHER`，设施结果 `target_type` 为 `HEAVY_SIMULATION`，详情保存 `simulated=true` 与方法标识。首页正式重车通行结果仍按原有 `HEAVY` / `HEAVY_PASS` 读取。

车辆参数或方案名变化时，当前沿线结论失效，数据库历史保留。修改起终点重新规划时，同一情景下的沿线重合设施通过后端核对后复用已保存结果。重置会清空当前情景。当前页面状态未做刷新恢复，已保存历史可在数据管理的“其他”任务中查询。

本轮实际数据库验证覆盖桥梁与隧道的参数读取、只读随机计算、人工调整保存、恢复原结论及重新规划前的结果核对。测试新增的4条记录已清理，任务总数恢复。前端构建与后端测试通过，弹窗及地图联动的浏览器可视化验收仍待人工完成。

## 已知边界

路线是双向简化网络的距离最短解，可能包含实际单行道路的逆向行驶，不构成实际行车许可。吸附距离可能较大，接入段不参与计算。设施清单只反映已有绑定，不代表现实沿线设施完整性。背景地图保留原有类别筛选和几何简化，规划路线本身包含实际经过的匝道。
