### 4.2 交付物现状（`模块开发/Seismic_Frontend_Fragility_Handoff_V1`）

冻结交付包：136 文件 / 13.16 MB，逐文件 SHA256；**6 条模型（5 条可评估）**：桥梁 B / C / D（PUBLISHED）+ Bridge C 归档（禁评估）+ 九顶山 S4、BCT-01（研究参考，未发布）。拟合样本：桥梁每座 240–260 个二元样本，隧道 20 条记录。10 个测试用例全通过。

**已接入平台的部分**：θ/β 逐值入库（`seed_fragility_models.sql`），`FragilityMath.java` 复刻对数正态 CDF 与「不排序/不截断/不兜底」策略，15 组基准最大误差 **1.11e-16**；地震动 AT2/TXT 解析规则照搬；前端绘制 DS1–DS4 超越概率曲线。

**尚未接入 / 与研究侧最新进展的落差**

1. 平台未做代码级调用（不 import、不起进程、不调 HTTP），属「参数复制 + 算法重写」；
2. **泥石流仍是平台预设的参数化简化模型**，莫东霖 10-20 已转向逻辑回归预测 6 小时发生概率，**该成果尚未进入平台**；
3. 隧道 IM 语义未打通（模型表为 `TARGET_INPUT_PGA`，平台喂自由场 PGA）；
4. 模型匹配仍按「灾害类型 + 资产类型」，桥型/跨径/墩高/年代/场地类别未参与；
5. 证据链（SHA256、bootstrap 95% 置信区间、溯源元数据）未带入平台；
6. 数据来源无公开文献 DOI，桥梁 3 条均为「2D RC 单柱墩代表模型」，隧道含假定配筋与合成基准——汇报时需如实说明来源性质。

### 5.2 交付物现状（`模块开发/路网韧性_程序网页工具代码_20261021`）

约 3.65 万行 Python，**66 个测试文件 / 699 个用例**，核心算法纯标准库无第三方依赖。指标体系：`FS`（安全，按灾前流量暴露加权）/ `FD`（冗余，Yen K 最短路 + 不相交增广 + 集划分得 Q1/Q2/ZD）/ `FT`（交通服务 `Pcab × Φ`，BPR + Frank–Wolfe）；综合 `FR = (FS+FD+FT)/3`；动态韧性积分 + T90/T100；N−1 关键道路。

原项目数据规模：节点 8,488 / 路段 11,742 / 桥隧 520 座 / 行政区 37 个。**注意：交付包内 `data/road_network.sqlite3` 为 66 表全空骨架，不含业务数据**，所有易损性、性能映射、维修工期、队伍数为 `source_kind='trial'` 试算假设。

### 5.3 与平台的集成状态：**未启动**

平台 `ResilienceService.java` 仅 47 行，道路状态按 `i%11 / i%4` 循环赋值，可达率 0.91 / 保持率 0.78 / 综合分 83 全为常量，恢复曲线为 5 点线性插值，区县分值由 `region_code.hashCode()` 加盐生成。平台内**无任何** Dijkstra / BPR / Frank–Wolfe / 蒙特卡洛实现。

**不可直接映射的口径落差**（推进集成前必须先对齐）

| 维度 | 研究工具 | 平台现状 | 一致 |
| --- | --- | --- | --- |
| 综合韧性 | `FR = (FS+FD+FT)/3`（0–1） | `resilienceScore` 百分制 + 等级 | ❌ |
| 冗余维 | `Q1 / Q2 / ZD` | 无对应字段 | ❌ 整维缺失 |
| 交通服务 | `Pcab`、`Φ`、`RT` | 仅 `reachable` + `detourRatio` | ❌ |
| 恢复时间 | `T90 / T100`（天） | `recoveryTimeH`（固定 72 小时） | ❌ |
| 恢复曲线 | 0–180 天逐事件阶跃 | 5 点线性 | ❌ |
| 关键道路 | N−1 `ID/IC/IT` 双榜 | 按伪造容量比排序 | ❌ |
| 灾前基准 | 可复算 `RS0/Q1_0/Q2_0/RT0` | 常量 125000 / 158000 | ❌ |

**三处结构性差异**（工作量的主要来源）：图模型（平台 `road_edge` 缺物理道路组、方向容量、桥隧子段切分、计算快照概念）；参数体系（研究侧 4 类版本化参数表 + 运行快照冻结，平台仅 `fragility_model`）；计算调度（研究侧分钟~小时级长任务 + 断点续算，平台为同步 REST）。
