## 部署基线

部署记录为阿里云 ECS / Ubuntu 24.04 单机架构：Nginx 提供 HTTP 入口和前端静态文件，代理 Spring Boot 8080 与 Bigemap 3000；本机 MySQL 保存业务数据，Bigemap 使用 Docker 与离线地图目录，后端使用 systemd 管理。
本地通过 Vite 的 development / production 环境文件区分地图地址、令牌和图层 ID。数据库与模型密钥通过后端环境变量配置。前端和 JAR 在本地构建，通过 SCP 上传，尚无自动发布流水线。
部署文档提供安装、数据迁移、服务管理、代理配置和故障排查；仓库不附带完整业务数据、离线瓦片或服务器配置文件，详细步骤见 [DEPLOYMENT.md](../../DEPLOYMENT.md)。

## 已知边界与待验证项

1. **专业分析方法**：灾害与韧性算法尚未定型，重车模块未提供真实路径求解。
2. **公网访问控制**：当前应用未实现登录鉴权，管理 API 支持修改和物理删除；入口访问限制与 HTTPS 状态需在服务器核对。部署示例仍以 HTTP 为基础。
3. **运行权限与端口**：systemd 示例以 root 启动，Bigemap 使用 privileged 容器；需评估服务权限。归档后的 Compose 示例仅发布回环端口，原部署记录为全接口绑定，实际网络状态未验证。
4. **模型工具兼容性**：AssistantToolService 当前将 parameters 放在工具外层，function 节点仅包含 name 和 description；需对照实际服务商接口验证带参数调用，本阶段不修改实现。
5. **助手耗时**：单次模型请求超时为 90 秒，最多 4 轮工具循环后再生成回答；总耗时可能超过 Nginx 的 120 秒等待时间。
6. **工具输出规模**：设施清单和任务查询有分页上限，重车及受损结果工具当前返回全部结果，需随数据量增长验证上下文规模。
7. **知识库更新**：文件随 JAR 打包，更新需重新构建部署；不是向量检索知识库。
8. **界面记录一致性**：本地 HomeView 未包含早期记录所述的饼图 confine / position 和雷达图 graphic；区域名实际使用 title。CSS 中仍有重复的雷达图容器规则。
9. **发布可复现性**：生产环境文件被 Git 忽略，拉取仓库后需自行配置；尚未建立自动化备份、迁移、回滚和构建版本对应记录。
10. **验证范围**：本次归档执行文档链接、凭据、Git 差异检查；未重新构建、未在线调用模型、未验证公网服务。仓库未发现自动化测试源码。
